一次渗流实验是一串有限的操作，操作的选择决定了哪些问题便宜、哪些昂贵。抽取一个构型并找出团簇、扫出整条耦合曲线、在窄条上枚举所有构型，是三个不同的问题。本章给出算法、代价，以及代码很快但估计量不对时仍然会存活下来的那些错误。

## 15.1 基本操作

几乎所有的格子算法都可以归结为：在不断插入边的同时维护连通分量。从 $n$ 个孤立位点开始。每一条开边要么合并两个分量，要么什么也不做。团簇统计量是分量大小的函数，所以数据结构只需要回答两个问题：*这个位点属于哪个分量？* 以及 *这个分量有多大？* 并查集（DSU）用摊还意义下几乎为常数的时间回答这两个问题。

## 15.2 并查集

每个分量用一棵有根树表示。`find(x)` 沿父指针走到根；`union(a,b)` 把小根挂到大根下面。有两个优化是关键。

- **按大小（或秩）合并。** 树的深度至多 $\lfloor\log_2 n\rfloor$，因为大小为 $s$ 的根只会挂到大小至少为 $s$ 的根上。
- **路径压缩。** 每次 `find` 把路径上的节点直接接到根上。一个节点若曾经昂贵，之后就会变便宜。

两者合用时，$n$ 个元素上的 $m$ 次操作代价为 $O(m\,\alpha(n))$，其中 $\alpha$ 是反阿克曼函数；对任何能放进可观测宇宙的 $n$ 都有 $\alpha(n)\le4$（Tarjan 1975）。只用路径压缩得不到反阿克曼界，只用按大小合并则是每次操作 $O(\log n)$。四种语言的库实现的都是两者的组合。

```
find(x):
    r = x
    while parent[r] != r: r = parent[r]
    while parent[x] != r:
        next = parent[x]; parent[x] = r; x = next
    return r

union(a, b):
    ra = find(a); rb = find(b)
    if ra == rb: return false
    if size[ra] < size[rb]: swap(ra, rb)
    parent[rb] = ra
    size[ra] += size[rb]
    count -= 1
    max_size = max(max_size, size[ra])
    return true
```

`max_size` 与 `count` 不属于抽象并查集；维护它们，是因为本图册的每个观测量都要用到。

## 15.3 Hoshen–Kopelman 标号

并查集是引擎，Hoshen–Kopelman 是喂给它的扫描（Hoshen 与 Kopelman 1976）。按行优先顺序访问位点。对每个占据位点，检查已经访问过的邻居（方格上是西边与北边）。若没有占据的邻居，分配一个新标号；若只有一个标号，复制它；若有两个不同标号，复制其中一个，并在等价表中合并两者。

扫描结束后，每个标号指向一个并查集根，团簇大小由一次标号遍历得到。$n$ 个位点的代价是 $O(n\,\alpha(n))$，内存为 $O(n)$。只要固定邻居表与扫描顺序，方法可以搬到任何格子；三角格子的邻居表更长，但每条边仍然只访问一次，复杂度不变。

两个实现细节很容易出错。第一，扫描后必须压缩等价表；一个已经并入其他标号的标号仍可能留在数组里。第二，位点渗流中空位点根本不该有标号，而键渗流中每个位点都在、只有开边才合并。把两种约定混在一起，会得到一张看似合理的团簇图，阈值却是错的。

## 15.4 Leath 生长

Hoshen–Kopelman 计算盒子里所有团簇；Leath 算法只计算一个团簇，即包含指定种子的那个（Leath 1976）。把种子放进队列并标记。弹出一个位点，检查邻居，把每个尚未访问的开邻居入队。输出是团簇及其边界；代价与实际触及的位点和边界边数成正比，而不是与盒子体积成正比。

算法是精确的：在种子占据的条件下，它从渗流测度中抽取种子的团簇，因为每个开邻居都被探索，每个闭邻居都被记为边界。当团簇远小于盒子时，它是正确的工具；当团簇绕盒子一圈时，它就不再便宜，因为探索终究会碰到大部分格子。

Leath 生长还能在不数遍所有团簇的情况下给出团簇大小分布。固定 $p$，从许多独立种子出发，记录每个团簇的大小，并在超过截断时停止。截断会给尾部带来偏差；应当报告它，而不是把它藏起来。

## 15.5 Newman–Ziff 扫描

按 $p$ 循环的蒙特卡洛研究在每个 $p$ 都重新抽一个构型，于是曲线上相邻两点来自不同样本。Newman 与 Ziff（2000、2001）去掉了外层循环。抽取 $m$ 条边的一个随机顺序，然后逐条加入。加入 $k$ 条边后，开边集合就是 $p=k/m$ 处键渗流的一个样本；不同 $k$ 的样本是嵌套的，不是独立的。

维护并查集、团簇数 $n_c$、最大团簇 $S_{\max}$，以及二阶矩
$$
M_2=\sum_{C}|C|^2 .
$$
初始时每个位点是一个单点，$M_2=n$。当一条边连接大小为 $a$ 与 $b$ 的两个分量时，
$$
M_2\;\mapsto\;M_2+2ab,
$$
因为交叉项 $2ab$ 出现，而两个旧的平方被 $(a+b)^2=a^2+2ab+b^2$ 取代。键渗流中每个位点都在，所以 $M_2/n$ 既是每个位点的二阶矩，也是平均团簇大小；位点渗流的分母则是占据位点数，不是 $n$。

整条扫描耗时 $O(m\,\alpha(n))$，内存 $O(n+m)$，用一条边序给出完整的 $S_{\max}(p)$、$\chi(p)$、$n_c(p)$ 曲线。代价是相关性：$k+1$ 处的点与 $k$ 处的点只差一条边，有效独立样本数远小于画出的点数。误差棒必须按独立的边序分块计算，不能把 $m$ 个点当作独立样本。

## 15.6 精确枚举与转移矩阵

对小系统，精确枚举既有竞争力，又能提供蒙特卡洛给不了的检验。宽 $w$、长 $L$ 的窄条若朴素枚举有 $2^{O(wL)}$ 个构型；转移矩阵把它降为 $O(L)$ 步，每步的状态空间随 $w$ 指数增长。状态记录当前切口上开位点的连通模式，而不是整段历史。每次加入一列的开闭模式，更新连通性，最后读出横穿指示。

转移矩阵对窄条是精确的；通过比较不同宽度，有限宽度标度可以提取 $p_c$ 与指数。代价随 $w$ 指数增长，所以在笔记本上 $w$ 只能到十几到二十。尽管如此，它仍是二维窄条高精度阈值以及星–三角精确值检验的标准途径。

## 15.7 该用哪一个

| 任务 | 算法 | 代价 | 注意 |
|---|---|---|---|
| 一个构型，全部团簇 | Hoshen–Kopelman | $O(n\,\alpha(n))$ | 需要一次完整标号遍历 |
| 一个团簇，稀有事件 | Leath 生长 | $O(|C|)$ | 用截断时有偏 |
| 整条 $S_{\max}(p)$、$\chi(p)$ | Newman–Ziff | $O(m\,\alpha(n))$ | 点与点相关 |
| 窄条精确阈值 | 转移矩阵 | 随宽度指数增长 | 只能小宽度 |
| 耦合网络 | 反复求巨分量 | $O(r(n+m))$ | 轮数 $r$ 依赖数据 |

前三种在四种语言的库中都有实现；第四种是研究工具，不在参考 API 里。`data/golden/parity.json` 中的一致性探针比较固定种子下的整数计数，这是在边序或随机数消耗的差异变成错误指数之前抓住它的唯一办法。

## 15.8 核心之外：自举、爆炸与侵入

另外三个算法在四个参考库中都有实现，并在实验室中展示。它们回答不同的问题，不应与 Bernoulli 采样器混为一谈。

**自举渗流。** 被占据的位点在时刻零活跃；空位点若至少有 $r$ 个活跃邻居，就被激活。更新是单调闭包，所以最终集合是最小不动点，与更新顺序无关。队列实现在活跃邻居计数首次达到 $r$ 的那一轮激活位点，时间为 $O(n+m)$。$r=2$ 时无限格子的阈值为零，但有限盒子在依赖 $L$ 的交叉点以上会充满；$r=3$ 与 $r=4$ 的阈值是正的。这个区别在实验 10 中可见。

**侵入渗流。** 每条边带独立同分布阈值。从种子出发，团簇反复接受边界上阈值最小、通向未访问位点的边。接受集合是侵入区域的生成树；贪心规则就是过程的定义，而不是对 Bernoulli 渗流的近似。二叉堆最坏情况为 $O(m\log m)$；按边界规模 $b$ 计常写作 $O(b\log b)$。环边被丢弃；实验室把它标为环拒绝，而不是多孔介质中防御团簇的 trapping 变体。

**Achlioptas 过程。** 每步抽两条候选边，乘积（或求和）规则保留两端分量较小的那条。在完全图上，这推迟巨分量并产生陡峭的有限尺度跳变。跳变不是热力学不连续：乘积规则在极限下连续，实验 11 的尺度检验展示了这一点。实现使用同一套并查集，并把轨迹报告为候选序列的精确函数。

这三个算法共享记录在 `data/golden/algorithms-v3.json` 中的四语言一致性契约：Python 与 JavaScript 生成探针，C++ 与 Julia 测试套件断言同一文件。Bernoulli 核心保留自己在 `data/golden/parity.json` 中的契约。正确性论证在第 19 章，仪器是实验 10–12；站点的“算法导读”把每条不变量链接到确切的源文件。

4.x 版又加入六条例程：Hoshen–Kopelman 标号、Bethe 不动点、配置模型巨分量、SIR 最终规模、位点 Newman–Ziff 扫描与消息传递。其中 Hoshen–Kopelman、Bethe 不动点、配置模型巨分量、SIR 最终规模与消息传递是确定性的；位点扫描消耗一个随机的位点顺序。前四条见第 22–23 章，位点扫描是 §15.5 的位点对应，消息传递是 §22.5 中 Bethe 递推的有限图形式。六条的金标探针都在同一个 `algorithms-v3.json` 里。

## 15.9 怎样读这些实现

JavaScript 引擎是浏览器运行的那一份；Python 包是可读的参考；C++ 头文件是快路径；Julia 包是带类型的路径，公开约定与其他三者相同。边序由 `build_lattice` 固定，随机流由 `docs/RNG.md` 固定，并查集由上文的伪代码固定。三者中任何一个改动都是破坏性变更：重新生成黄金值、升版本，并在第 14 章记录更正。

本章的算法也是图册能在浏览器里实时画曲线的原因。$128\times128$ 的开边界格子有 32512 条边；一次 Newman–Ziff 扫描是几百万次并查集操作，分块执行时完全在一帧的预算之内。实验室与库走的是同一条代码路径，没有一个单独的“演示”实现会悄悄漂移。
